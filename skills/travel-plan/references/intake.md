# 使用者資訊取得：任意輸入 → 去識別化 JSON

> 對應計畫書 §4 全部。本檔是 `SKILL.md` 啟動流程第 2～4 步的完整規格。
> 去識別化規則與 `trip_context.json` 範例見 `references/privacy.md`；欄位型別見 `templates/trip_context.schema.json`。

## 三種取得方式（依優先序，由上往下退）

### 1. 使用者已有檔案（預設路徑）

任何 agent 讀得懂的格式都收：md、txt、訂房確認信、行事曆匯出、截圖、docx、pdf。直接讀並抽取，**不要求使用者重填表格**。

這條之所以是預設，是因為真實使用者手上通常已經有東西，而且形態混雜——常見的是同一個檔案裡同時有：半結構的行程草稿 ＋ 整段貼上的訂房確認信 ＋ 手打的班機時刻。抽取時要能容忍這種混合，不要因為格式不整齊就退回問卷。

有檔案讀寫能力時，請使用者把原始檔放進 `trips/{trip}/private/input/`（**永不進版控**，見 `references/privacy.md`）。無檔案讀寫能力時，使用者直接貼進對話即可，但仍要提醒「這段內容含個資，後續產出不會回填」。

### 2. 沒有檔案 → agent 引導式提問

**一次問一批 3~5 題，不逐題來回。** 順序：先問決定性的（目的地、日期、班機時刻、住宿區位），其餘用預設。**每題附上「不回答會怎樣」**，讓使用者能安心跳過。

可直接把 `templates/trip_profile.template.md` 的對應段落貼給偏好填表的使用者，但那是選填輔助，不是主要入口。

### 3. 什麼都不想給

除目的地外全部走預設推斷，並在 `progress.md`「待覆核的推斷值」區塊**逐項列出**。流程不中斷。

## 必須抽出的欄位與抽不到時的行為

| 欄位 | 抽不到時的行為 |
|---|---|
| **目的地** | **唯一硬停**：輸出 `SKILL.md` §1.3 的固定句並中止流程，不得續問其他事項 |
| 旅遊起訖日期 | 反問（影響季節、資訊時效、天數） |
| 出發/回程時刻與機場航廈 | 推斷該航線常見班次，標記待覆核（影響首尾 buffer，見 `references/sections/10_itinerary.md`） |
| 航空公司 | 推斷該航線主流航司，標記待覆核（影響行李規範，見 `references/sections/02_immigration.md`） |
| 住宿區位 | 推斷該目的地常見住宿區，標記待覆核（影響景點分區，見 `references/sections/09_materials.md`） |
| 成員結構 | 預設「一般成人旅客」，仍產友善度評分但不做特殊加權 |
| 旅行風格、指名景點、預算、電信商、來源偏好 | 全部走「留空即預設」，不中斷 |
| 飲食限制/偏好（`party.diet_notes`） | 原始輸入或使用者回覆裡**有明講**（如不吃辣、素食、過敏原）才抽出填入；沒提到就留 `null`，09 美食選材依熱門度為準，不得自行臆測套用 |

**所有推斷來的值都要寫進 `trip_context.json` 的 `inferred_fields`**，並同步到 `progress.md` 的「待覆核的推斷值」。使用者一旦更正，回頭改 `trip_context.json` 並記錄於「決策紀錄」。

## 為什麼中介產物是 JSON 而不是散文

抽取結果不留在散文裡，一律整理成 `trip_context.json`：

- **下游 11 個主題都要讀它**。固定欄位不會讀歪；散文每次讀都要重新理解一次，且不同主題可能理解出不同答案。
- **去識別化檢查更可靠**：比對「有哪些欄位、值是什麼」，比在散文裡抓漏網的姓名或訂位代號穩得多。
- **與素材庫同格式**，整套 skill 只需要一條解析路徑。
- 人要看的版本另外用 md 呈現，不影響閱讀。

原始輸入（含個資）留在 `private/`，`trip_context.json` 的 `provenance` 欄位只記錄來源路徑，不複製內容。

## 產出後的人工關卡

`trip_context.json` 產出後、**第一次 commit 或第一次進入主題執行之前**，必須把去識別化結果攤給使用者過目，明確問兩件事：

1. 推斷值（`inferred_fields` 列出的）對不對？
2. 有沒有不該保留、或不該被刪掉的欄位？

這是不可跳過的人工關卡，不論當下環境是否有 git。
